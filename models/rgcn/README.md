# R-GCN for Drug–Disease Link Prediction

This module trains a **Relational Graph Convolutional Network (R-GCN)** to predict drug–disease relationships using the knowledge graph generated by the **KG constructor pipeline**.

The model learns vector representations of drugs and diseases based on graph connectivity and can generate ranked predictions of potential therapeutic relationships.

The system supports two prediction tasks:

- **Disease → Drug recommendation**
- **Drug → Disease prediction**

Both tasks use the same triple structure:

(drug, INDICATION, disease)

Only the ranking direction changes depending on the configured task.

Each evaluation run also logs its metrics to `models/performance_leaderboard.csv`,
which acts as the shared results table for the project.

# Overview

The R-GCN pipeline consists of five stages:

1. **Prepare Graph** (`00_prepare_graph.py`)  
   Converts canonical triples from the KG constructor into indexed graph artifacts used by the R-GCN model.

2. **Validate Graph Data** (`01_load_data.py`)  
   Loads and validates prepared graph artifacts and prints graph statistics.

3. **Train Model** (`02_train.py`)  
   Trains an R-GCN encoder with a DistMult decoder for link prediction.

4. **Evaluate Model** (`03_evaluate.py`)  
   Evaluates the trained model using filtered ranking metrics.

5. **Run Inference** (`04_infer.py`)  
   Generates ranked predictions for a given query entity.

# How the Model Works

The architecture combines three components.

## R-GCN Encoder

The encoder learns node representations by aggregating information from neighbours while considering relation types.

h_i^(l+1) = σ( Σ_r W_r^(l) Σ_{j∈N_i^r} h_j^(l) / |N_i^r| + W_0^(l) h_i^(l) )

Where:

- h_i^(l) = embedding of node i at layer l  
- N_i^r = neighbours connected via relation r  
- W_r = relation-specific transformation matrices  

Basis decomposition is used to reduce the number of parameters.

---

## DistMult Decoder

The decoder scores triples using a bilinear function:

score(h, r, t) = h^T R_r t

Where:

- h = source entity embedding  
- t = target entity embedding  
- R_r = relation embedding  

Higher scores indicate more likely relationships.

---

## Negative Sampling

During training, artificial negative examples are created by corrupting triples.

Example:

(drug_A, INDICATION, disease_X)  → positive  
(drug_B, INDICATION, disease_X)  → negative  

This teaches the model which relationships should not exist.

---

## Filtered Ranking

During evaluation, known triples are removed from candidate rankings so the model is not penalized for predicting valid relationships that already exist in the graph.

# Supported Prediction Tasks

## Disease → Drug Recommendation

Given a **disease**, rank candidate drugs that may treat it.

Query entity type:

DISEASE

Candidate entities:

DRUG

Example:

Query: DOID:2841 (Asthma)

Top predictions:

1. Albuterol  
2. Salbutamol  
3. Terbutaline  

---

## Drug → Disease Prediction

Given a **drug**, rank diseases that may be treated by it.

Query entity type:

DRUG

Candidate entities:

DISEASE

Example:

Query: DRUG:METFORMIN

Top predictions:

1. Type 2 Diabetes  
2. Polycystic Ovary Syndrome  
3. Insulin Resistance

# Configuration

Configuration files are located in:

models/rgcn/configs/

Example configuration (`baseline.yaml`):

```yaml
seed: 42

data:
  triples_path: "kg_constructor/data/output/triples/triples.filtered.csv"
   processed_dir: "models/rgcn/data/processed"

task:
  name: "disease_to_drug"
  target_relation: "INDICATION"
  query_entity_type: "DISEASE"
  candidate_entity_type: "DRUG"
  context_relations:
    - "INDICATION"
    - "CONTRAINDICATION"

split:
  train_ratio: 0.8
  val_ratio: 0.1
  test_ratio: 0.1

training:
  epochs: 600
  lr: 0.001
  weight_decay: 0.0001
  dropout: 0.2
  emb_dim: 128
  num_bases: 3
  num_layers: 2
  neg_k: 50
  eval_every: 10
  hits_k: [1,3,10]
  device: "cpu"

runs:
   out_dir: "models/rgcn/runs"
